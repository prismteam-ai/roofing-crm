# P3 CRM staging operations

This supersedes the historical P2 operation rehearsal. The original README remains preserved. Region is validated as `us-east-1`; stage is `p3-review`. No operation in this repository has been executed against AWS by the CRM implementation lane. Live account work, maps and inference remain parent-owned execution gates.

## Build and local checks

Use Node24. Install with `pnpm install --frozen-lockfile --ignore-scripts`; no dependency build hooks are required. The first offline install lacked registry metadata; the authorized normal frozen retry succeeded without hooks. `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm contract:check`, `pnpm build`, `pnpm lambda:package`, `pnpm lambda:emulate`, `pnpm cdk:synth`, `pnpm benchmark`, and `pnpm test:map-browser` are local-only. The dedicated map browser suite fulfills both CloudFront and AWS map requests with synthetic local fixtures and verifies the real MapLibre adapter, origin-only referrer, attribution, and failed-style offline point retention; it makes no live map request. Run the ordinary browser suite separately for real and synthetic services.

A staging release must be committed and clean **before** packaging. Set `PRISM_STAGE=p3-review PRISM_REGION=us-east-1`, then build and package. Frontend `release-identity.json`, Lambda `PACKAGE_PROOF.json`, `build/release-package.json` and `/api/health` bind exact application HEAD/tree, dirty status, deterministic build ID, contract hash/version, stage and region. Local development explicitly reports stage `local` and may report a dirty tree. Build IDs are hashes of the complete identity, not a deploy-time mutable string. Contract0.2.1 stays byte-pinned.

## Parent execution inputs

Every `pnpm run deploy`, `pnpm run smoke`, `pnpm run evidence`, `pnpm run rotate-access`, and `pnpm run destroy` defaults to a zero-service-call plan. For example, `pnpm run deploy --execute`. Only an explicit `--execute` permits effects, and only with `PRISM_CLOUD_EXECUTION_APPROVED=yes`; human MFA, budget alert and no-production-resource attestations must also be `yes` in `PRISM_HUMAN_MFA_CONFIRMED`, `PRISM_BUDGET_ALERTS_CONFIRMED`, `PRISM_NO_PRODUCTION_RESOURCES_CONFIRMED`. Set private `PRISM_EXPECTED_ACCOUNT_ID`, exact `PRISM_EXPECTED_HEAD`, `PRISM_EXPECTED_TREE`, `PRISM_EXPECTED_ARCHIVE_SHA256`, `PRISM_EXPECTED_SNAPSHOT_ID`, `PRISM_EXPECTED_SNAPSHOT_DIGEST`, `PRISM_DEPLOY_REGION=us-east-1`, `PRISM_DEPLOY_ASSET_BUCKET` (dedicated `prism-p3-*`), and an absolute private `PRISM_PRIVATE_OPERATIONS_DIR` outside the repository and returned evidence. Mixed ambient AWS regions are rejected. `PRISM_AWS_ACTUAL_USD`, `PRISM_AWS_PENDING_USD`, `PRISM_P3_ACTUAL_USD`, `PRISM_P3_PENDING_USD` include pending commitments; guards cap AWS subtotal35 and aggregate75. Parent should target the lower35 aggregate target and preserve the separate model6 ceiling.

Deployment additionally requires Oracle's exact CloudFront HTTPS `PRISM_ORACLE_ORIGIN`, exact `PRISM_ORACLE_EXPECTED_BUILD_ID`, `PRISM_REVIEW_SECRET_ARN`, `PRISM_SHARED_TABLE_ARN`, and an exact task-scoped `PRISM_CFN_EXECUTION_ROLE_ARN`. The build wrapper computes exact HEAD/tree/build ID, places them with stage/region/Oracle link in Turbo globalEnv hashed inputs, and the frontend independently rechecks the pins. Turbo caching is disabled as an additional guard, so metadata-only commits and link changes cannot reuse stale assets. The deploy operator rebuilds the frontend at the pinned clean source with the exact Oracle link before any AWS call and checks the complete frontend/Lambda identity. The operator verifies caller account, bucket owner/region/public-access block, clean source, archive digest and frontend/Lambda build equality before deploying. ZIP upload goes only to `prism-p3/crm/lambda/<sha256>.zip` in the explicit existing private deployment bucket. CDK uses `BootstraplessSynthesizer` and `Code.fromBucket`; it creates no bootstrap bucket, ECR repository or asset-deployment custom Lambda. Static assets are synced only to this exact stack's frontend bucket and root/index/identity invalidated. All AWS CLI operations receive the validated region explicitly. Cloud/provider failure output and secret arguments are redacted. Private receipts bind source/package and completed steps; reruns do not silently skip new configuration.

Deploy first with `PRISM_ENABLE_MODEL=false PRISM_ENABLE_MAP=false`. `EnableMap=true` additionally requires `PRISM_LIVE_MAP_APPROVED=yes`; `EnableModel=true` requires `PRISM_LIVE_INFERENCE_APPROVED=yes`. Those guards permit enablement only after the parent has completed the separate account/current-price gates. No live action runs during packaging or synthesis.

`smoke --execute` reads the review access code privately from stdin, verifies exact health/build, unauthenticated401, authenticated map config/search, and logout. `evidence --execute` launches a clean browser, asserts exact current query hash and IDs before capture, masks all identifying rows/private observation fields using native screenshot masks, and records only counts/digests plus the exact masking selectors. Product data is not masked in the app. Raw provider traces, codes and map keys are excluded. Screenshot capture additionally requires rendered DOM HEAD/tree/build ID/stage/region to equal both current API health and the exact SHA-pinned local package. It records hashes of loaded same-origin JS/CSS assets and the frontend configuration. If supplied, `PRISM_ORACLE_ORIGIN` must match the rendered Oracle link. Optional `PRISM_EXPECTED_FRONTEND_CONFIG_SHA256` pins SHA256 of `JSON.stringify({oracleOrigin,region,stage})` in that key order. Optional `PRISM_EXPECTED_FRONTEND_ASSET_MANIFEST` names a private JSON object mapping relative `assets/<file>.js|css` paths to SHA256; `PRISM_EXPECTED_FRONTEND_ASSET_MANIFEST_SHA256` pins its exact bytes. Every expected asset must be observed with its expected digest, and unlisted loaded assets are rejected before capture. No map-config response or key-bearing map URL is hashed into this public metadata.

`rotate-access --execute` reads the new code from stdin, rotates key version/signing material and preserves other shared-secret fields including `locationMap`; existing sessions fail after the bounded60s secret cache expires. It never prints secret JSON. Never put access codes in command arguments or env values.

`destroy --execute` additionally requires `PRISM_TEARDOWN_APPROVED=yes` and `PRISM_ARCHIVED_EVIDENCE_SHA256`. It revokes access before deleting the exact stack and reports retained resources. Review data is RETAIN by default; deleting the stack does **not** prove recurring charges ceased. Parent must explicitly review frontend bucket versions, leads, shared session/campaign table, logs, deployment assets, shared secret and Oracle-owned map key, then record the final cleanup/billing decision. No automatic14-day deletion occurs.

## Restricted map

Amazon Location StandardV2 has no legacy Map resource. Oracle owns the optional finite-expiry browser key, scoped to `arn:aws:geo-maps:us-east-1::provider/default`, exact permitted map action(s), and exact CRM CloudFront origin referer. Create it only after the first CRM domain exists. Do not put its value in Git, environment variables, CFN parameters/outputs, frontend assets, logs, screenshots or return archives. Oracle privately merges `{locationMap:{apiKey,allowedOrigin,region,style,expiresAt,restrictionsDigest}}` into the existing shared secret. Values are fetched only through authenticated no-store `/api/map-config`; omission, invalid origin/expiry or disabled map keeps the offline map.

The adapter permits only `https://maps.geo.us-east-1.amazonaws.com/v2/` Standard descriptor/sprites, tiles and glyph paths; it rejects other hosts, schemes, credentials, fragments, geocoder/routes and arbitrary query keys. Key attachment happens only after that check. CSP allows this one map origin; browser referrer policy is `strict-origin-when-cross-origin` so cross-origin requests contain the exact CRM origin without query/property data. Provider attribution is retained and a conspicuous attribution link is shown. Overlapping projected markers are grouped with every member ID retained; selected groups are emphasized. Map/list identity is exposed as the complete coordinate-bearing ID set, not inferred from cluster count. Tile/style errors retain geographic points, radius/pin controls and an accessible schematic fallback.

## Model policy and campaign

Default direct model is `amazon.nova-micro-v1:0` in `us-east-1`; inference profile IDs and other regions are rejected. NovaLite `amazon.nova-lite-v1:0` is permitted only after the predefined eight-prompt Micro campaign fails and its **one** prompt repair fails. The same fixed corpus runs against the deterministic parser and live endpoint. Unknown/unavailable evidence stays explicit; arbitrary SQL/filesystem/browser/secret requests, instruction overrides and ambiguous distance units are refused before any provider call. Follow-ups receive an explicit unchanged area query.

The shared Dynamo table stores atomic durable counters for BOTH user requests and actual Converse calls:120 total,60 per UTC day,20 per session/hour. Total counters have no TTL, preventing redeploy resets. Each request has at most3 turns,2 typed read calls,50 retrieved rows,12000 aggregate measured tokens (stricter than input-only),1000 output tokens/call and15s deadline. Full server evidence stays available for final citations; model context is compact and explicitly reports omitted rows. Every Converse call reserves the full12000-input/1000-output worst-case cost, with a6USD campaign cap. Failed attempts retain reservations. Usage consistency is checked and measured usage/cost plus hashed subject/prompt, model/region and bounded source/query identities are persisted; no raw provider trace is retained. Native provider throttling/unavailability is normalized at the Converse boundary without retaining raw SDK errors; it also falls back to deterministic evidence. Failed attempts keep their durable reservation and a sanitized audit records reserved cost, incomplete measured usage and unmeasured call count. The real SDK adapter fixes maxAttempts1; a socket-free SDK429 regression verifies one actual request-handler invocation. Model cap/timeout falls back to the deterministic parser with an explicit caveat, never a silent live-model claim.

Parent privately supplies current `modelPrices[modelId]` in the shared secret: `{modelId,region:'us-east-1',inputUsdPerMillion,outputUsdPerMillion,verifiedAt,source}`. `verifiedAt` must be within24h and not in the future; `source` must be the exact official pricing page or Bedrock regional price-list path. Parent verified Micro0.035 input/0.14 output and Lite0.06/0.24 USD/M on2026-10-27; this document is not a future price quote or permission to invoke. The runtime refuses stale/missing prices.

`pnpm run campaign` emits only the finite plan. Parent invokes `pnpm run campaign --execute` with both approval guards, exact expected head/tree, costs, review origin, model ID, prompt revision and private operations directory; code is stdin. It executes the eight fixed cases once, records failures and aggregate usage/cost without raw rows. Do not loop retries. For a Micro repair deployment set `PRISM_MODEL_PROMPT_REVISION=repair-1` and provide `PRISM_MICRO_BASE_FAILURE_REPORT`. For Lite additionally supply `PRISM_MICRO_REPAIR_FAILURE_REPORT`; deploy validates complete failed eight-case reports and writes their digests to the shared durable quality gate. Hosted runtime checks that same gate before repair/Lite. Reports do not refund any allowance. Preserve all attempted reports and stop at the ceilings.

Report-level municipal context is authenticated metadata only: official report/page URL, verified title, retrieval date, explicitly unstated declared report period, separately labeled observed sale-date range, normalized exact-PIN match method, building-year proxy and partial-history caveats. It is not a roof inspection or ten-year ownership claim.
