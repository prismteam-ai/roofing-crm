# P4 grounded retrieval and presentation

The user's original assessment scope requires the model to consume retrieved evidence. That alignment overrides the later handoff choice that put a model-only router before retrieval. The earlier `one-call-tool-router-v1`/`bedrock-tool-routed` architecture and its local proofs remain historical attempts, not acceptance for this implementation. The current architecture is `one-call-grounded-selection-v1`, mode `bedrock-grounded`. It retains the same durable P4 allowance and existing `p3-review` resources; no counters or budget history are reset.

## One retrieval, one grounded model call

1. Apply deterministic injection/unsupported-operation guards and parse the shared typed query. Snapshot, map center, predicates and active-map/page bounds are fixed before any read or provider call. Unsupported ownership tenure remains distinct from observed reported-sale age.
2. Run exactly one bounded Oracle search, with at most50 retrieved records. Keep its full response server-side for rendering, grounding checks and fallback.
3. Project only allowlisted retrieved facts into short row ordinals0..49: roof age/basis/confidence; acquired roofing status counts and observed open duration/date; reported-business role; first distinct literal license status/type/identifier and BBB letter observation with dates/match confidence; observation counts; and latest reported-sale date/partial history class. Property IDs, parcel IDs, addresses, source descriptions/caveats/intake bodies, reported business names, owner names/contacts, URLs and raw provenance are absent from this projection. No fact is created by the model.
4. Send the natural-language question, fixed query and minimized retrieved evidence to one Bedrock Converse call. The only forced tool is `selectGroundedEvidence`. Its strict schema accepts a list of ordinal plus one fixed reason category. No factual prose, query, ID, URL, arbitrary key or second turn is accepted.
5. Validate unique in-range ordinals and require a nonempty selection when projected records exist. Validate each specific reason against the supplied evidence; `context_match` permits general relevance without inventing an unsupported claim. The server renders exactly the selected authoritative source rows in the accepted order, deriving citations and all counts/facts from retrieval.

The conservative12,000-token reservation counts serialized request bytes plus the1,000-output allowance. Rows are projected in source order until that bound is reached. A context prefix may contain fewer rows than the retrieved page; its size and omission state are explicit. Selection can omit candidates from presentation, but never changes the actual total matches. The response distinguishes selected presentation count, retrieved-page count, minimized context count and full server match count and states that selection is not complete coverage. The regular map/list query remains an independent path to the bounded source page.

The trace binds typed query, snapshot, query hash, full response digest, minimized `evidenceDigest`, `minimizedRowCount`, `retrievedRowCount`, selected ordinals, rationale categories, presentation-tool name and validated argument digest. Model usage audits also record the evidence digest and minimized row count. The model sees minimized retrieved facts; no active label claims it saw no evidence. Raw provider text is not retained.

## Honest fallback and budgets

`deterministic-fallback` is not model success. If provider/selection/allowance processing fails after retrieval, fallback reuses the same cached source response. It cannot issue a second Oracle search. A pre-read allowance/price failure may produce one deterministic read; an already attempted failed read is not repeated. Unsafe/unsupported prompts return `refused-before-model` with neither read nor provider invocation.

The fixed partition remains `campaign#prism-assessment-p4`, separate from historical P3. P4 totals have no TTL and are never refunded/reset:80 requests,80 Converse reservations and USD3 conservatively reserved; daily caps60 and session/hour caps20 remain. SDK attempts are one. Only Micro base starts enabled; one measured failed campaign for this architecture may grant one repair, then the already enabled Lite alternative only after its measured failure. Old routing or P3 reports do not qualify.

The overall grounded retrieval/provider deadline is bounded at28seconds, accounting for time already spent in allowance/price preparation. The runtime Oracle client uses20seconds, campaign/browser agent requests28seconds, and Lambda29seconds. These finite changes address measured cold startup; they are not unlimited retries or timeouts. The template verifier checks the29-second bound. Current official prices remain verified for24hours; stale pricing uses only the approved fixed anonymous regional AWS URL, exact four SKUs, no redirects,5-second deadline and2MB cap, after a durable request reservation. Failure cannot authorize a model call at stale prices.

## Source semantics retained

The CRM reported-sale filter uses a separate `reportedSaleYears` URL field. Legacy tenure links remain distinct and clearable, never converted to sale-age data. The reported-sale predicate uses the latest observed `reported_sale` date only, excluding unknown/future values; neither transfer dates nor `recorded_transfer` events substitute for sale age or establish tenure.

Issued-only permits remain unknown open/closed and cannot produce open duration. Explicit-open duration ends at the status observation date, not an assumed later date. Proposed roofing work does not prove completed work or roof installation. The Troy source business applicant is not a verified contractor role. Literal license status, source observation date and match confidence remain visible; a numeric score is not converted into a BBB letter rating. Source-link rendering remains restricted to credential-free HTTPS.
