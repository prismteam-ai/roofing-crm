# Security and privacy

Keep four classes separate: public assessment artifacts, protected source
observations, CRM lead state, and access/model operational state. Public parcel
and site-address evidence is distinct from owner names/contacts and restricted
source intake. The public publication allowlist excludes protected observations,
provider records, owner/contact fields, credentials and operational account data.
Existing public CIDs remain historical assessment products, not proof of current
Atlas conformance or erasure guarantees.

The signed review session is verified server-side and checked against durable
revocation/expiry state. Cookies and no-store responses, session-scoped lead
identities, optimistic versions and idempotent creation prevent namespace leaks
and duplicate work. Request/session generations prevent late responses from
replacing current UI state. Codes and signing material are not frontend assets,
command arguments, browser recordings, Git content or evidence attachments.

Natural-language input cannot expose arbitrary SQL, files, browser/network tools,
secrets or outreach. Unsupported/mixed/ambiguous material requests are refused
before evidence/model use with a typed ledger. Oracle responses pass schema,
snapshot, place, result bounds, shared predicates and source-order checks. The
model receives a compact allowlisted projection; it returns strict row ordinals
and rationale categories. It cannot supply factual prose, IDs or citations.
The server renders authoritative facts. Missing evidence and fallback are visible.

API/session quotas, bounded rows/tokens/deadlines, Lambda reservations and API
rate/burst controls complement a durable model request/call/cost envelope. A
provider call reserves worst-case allowance before invocation; failed and
unmeasured attempts retain reservations. Price freshness is bounded and verified
against approved official pricing sources. No identity rotation or counter reset
is a budget strategy. Final limits and their actual enforcement are pinned in
runtime and operator evidence, not inferred from a historical document.

Use strict Zod/TypeScript boundaries, injected effectful adapters and scoped IAM.
No CRM source scraping or public provider upload is part of normal application
behavior. Final review must scan full Git history, packages, screenshots and the
return for secrets/private data, inspect dependency/license findings and IAM,
and verify CSP/CORS/CSRF/cookies/security headers and access revocation. Local
synthetic tests do not establish those hosted/account facts. Media remains on
hold until both required reviews explicitly allow it.
