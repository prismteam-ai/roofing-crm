# Security and privacy

Keep four classes separate: public assessment artifacts, protected source
observations, CRM lead state, and access/model operational state. Public parcel
and site-address evidence is distinct from owner names/contacts and restricted
source intake. The public publication allowlist excludes protected observations,
provider records, owner/contact fields, credentials and operational account data.
Existing public CIDs remain historical assessment products, not proof of current
Atlas conformance or erasure guarantees.

The signed review session is verified server-side and checked against durable
revocation/expiry state. Cookies and no-store responses, session-scoped lead
identities, optimistic versions and idempotent creation prevent namespace leaks
and duplicate work. Request/session generations prevent late responses from
replacing current UI state. Codes and signing material are not frontend assets,
command arguments, browser recordings, Git content or evidence attachments.

Natural-language input cannot expose arbitrary SQL, files, browser/network tools,
secrets or outreach. Unsupported/mixed/ambiguous material requests are refused
before evidence/model use with a typed ledger. Oracle responses pass schema,
snapshot, place, result bounds, shared predicates and source-order checks. The
model receives a compact allowlisted projection; it returns strict row ordinals
and rationale categories. It cannot supply factual prose, IDs or citations.
The server renders authoritative facts. Missing evidence and fallback are visible.

API/session quotas, bounded rows/tokens/deadlines, Lambda reservations and API
rate/burst controls complement a durable model request/call/cost envelope. A
provider call reserves worst-case allowance before invocation; failed and
unmeasured attempts retain reservations. Price freshness is bounded and verified
against approved official pricing sources. No identity rotation or counter reset
is a budget strategy. Final limits and their actual enforcement are pinned in
runtime and operator evidence, not inferred from a historical document.

Use strict Zod/TypeScript boundaries, injected effectful adapters and scoped IAM.
No CRM source scraping or public provider upload is part of normal application
behavior. Final review must scan full Git history, packages, screenshots and the
return for secrets/private data, inspect dependency/license findings and IAM,
and verify CSP/CORS/CSRF/cookies/security headers and access revocation. Local
synthetic tests do not establish those hosted/account facts. Media remains on
hold until both required reviews explicitly allow it.

Request accounting: the P5 durable lifetime request counter permits at most 100 validated agent executions, including empty results and failed invocations. Pre-model refusals do not enter that execution counter. All model-endpoint attempts, including refusals, consume the separate 80/day and 40/session-hour endpoint quota. Converse has its own durable 100-call ceiling. Earlier phase counters remain unchanged.

The unreleased P5 0.4.0 contract was finalized with an optional, bounded
`ownership.reportedOwnerObservations` field before its first P5 deployment. The
canonical contract hash is authoritative; the manifest records the superseded
unreleased draft. This adds private typed source observations without changing
immutable public snapshot bytes. Private API responses can include the source
Owner name with explicit uncertainty; the model receives the existing explicit
minimized fact allowlist, which omits these names and raw source records. A
captured-provider regression checks both the retained private API observation
and absent model input. Screenshots mask `.private-source-reported-owner`.

The private v7 extension retains all eight v6 data files byte for byte and adds
one official Troy Real Property Assessing Report case observed through the normal
public UI. All 39 displayed fields remain in its protected source table, with
manual-transcription provenance; there is no captured server body or bulk-source
claim. Explicit Owner Name 1/2 and Owner mailing fields are private observations,
with no known ownership-effective date or related permit event. These fields
remain excluded from model input and public publication.

This assessment association uses one exact normalized printed parcel number and
exact CITY OF TROY jurisdiction. Source and county street text differ: no number-
word/suffix equivalence or fuzzy address match is asserted. The source association
is medium confidence and does not verify a building, unit, roof, residence or
current legal ownership. Owner and roof views retain that limitation. The
separate owner-mailing-to-site comparison stays unknown. A reported Owner State
of MI supplies one spatially usable regional/in-state mailing observation with
source provenance, not a county-local or residence conclusion.

The source commercial-building summary year 2022 adds one low-confidence
building-year proxy. The raw slash-formatted sale string in 2012 has no observed format label:
the normalized sale date remains null, and the raw source value is retained. It
cannot prove uninterrupted tenure; the source also describes a later parcel split.
The local v7 proof reconciles 3,747 owner observations (3,746 prior Rochester
observations unchanged) and 39,282 normalized permit observations unchanged.
One current source case is not municipal coverage or evidence of source exhaustion.
