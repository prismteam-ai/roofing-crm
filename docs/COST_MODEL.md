## Retention, rollback and teardown

Runtime retention is finite and follows the current explicit review contract. The original assignment does not specify a fourteen-day lifetime. A chosen review window requires an actual configured/read-back date for every dependency, including the CRM map configuration and native map key; the earliest enforced expiry controls. A later source/documentation revision does not extend that date. Use the approved PR and latest external access receipt for the real retained-through limit. One-hour sessions, capability-until-rotation and runtime/map retention are different controls. No permanent availability or automatic extension until employer acknowledgment is promised. Keep budget notifications active; notifications do not prove automatic teardown.

Teardown is prepared only. In each repository, `pnpm run destroy --dry-run` shows the guarded plan; actual `pnpm run destroy --execute` requires fresh scoped authority, exact stack/account/region/source pins, an exported-evidence digest and explicit teardown acknowledgment. Revoke review access and verify denial before removing endpoints. Remove CRM before its Oracle dependency. Preserve rollback and shared bootstrap assets unless separately approved. Check retained S3 versions, DynamoDB operational records, logs, secrets, map keys and CDN resources, then verify inventory, endpoint denial, residual storage and billing. Under the illustrative 10 GB S3 assumption, Standard storage alone would be about USD0.23/month before allowances; actual retained versions and other resources can add cost. AWS deletion cannot retract IPFS replicas. See [deployment](DEPLOYMENT.md) and [security](SECURITY_PRIVACY.md).
