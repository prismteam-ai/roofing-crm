# Release checklist

Before any source promotion: preserve original requirement rows and source authority, freeze schema/rights/pins, run `pnpm run ci:verify` from a clean clone, reconstruct the exact bundle/patch, compare repeated package identities, and independently review the final diff and evidence.

Before hosted acceptance: verify the exact candidate account/region, guarded CDK deployment, Lambda package and frontend manifests, snapshot/contract identity, resource tags, 90-day logs, active tracing, quotas, cost reserve and all semantic browser/API/model workflows. Confirm private canaries never appear in logs, traces, screenshots, Git or the return. Record actual alarm trigger/resolve separately from mock validation.

Before media or submission: obtain the required operator and independent lead greenlights on original outcomes, not only safe code paths. No video/audio/subtitles, Git push, remote branch, PR, Ready transition, employer message, new real public root, Atlas/IPNS or internal registry mutation is performed by this checklist. Actual GitHub Actions becomes a post-push gate and cannot be called passed beforehand.

At closeout: revoke/delete temporary deployment access, preserve both new and rollback review stacks, retain one compact reconstruction-grade return with checksums/verifier and explicit bulky-artifact indexes, and keep secrets/private intake out of that return.
