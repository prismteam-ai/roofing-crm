# Release checklist

## Freeze and reproduce

Preserve the original requirement rows, assignment and all dated history. Freeze architecture, contract/data pins and the final free-only source disposition. No paid source is required or purchased. Run `pnpm run ci:verify` from fresh clones with Node 24/pnpm 11.25.0, reconstruct exact bundles/patches, compare two deterministic package/frontend builds, and independently review the final diff and privacy evidence. Failed attempts keep their original identities.

## Promote the exact source

Update only the existing `review` stacks in `us-east-2`. Verify the guarded operator/account/region, measured Lambda and frontend manifests, upstream Oracle bindings, contract/snapshots, tags, 90-day logs, tracing, quotas and cost exposure. Preserve rollback stacks and admitted artifacts. A source-independent external release receipt binds the final heads/trees and actual deployments; do not place an anticipated final Git/build hash in source.

The accepted baseline's scoped runtime/access receipt already exists and is pinned in [release status](RELEASE_STATUS.json). A later documentation release still needs its own clean-clone and hosted first-use acceptance, not a relabeling of baseline evidence. Exercise three fresh desktop contexts, one mobile context and one direct API/MCP client, cold/warm behavior, map, live agent, lead persistence/history and signed expiry/revocation. Record actual alarm trigger/resolve separately from mocks. Verify private canaries never enter logs, traces, screenshots, Git or the return.

State the actual retained-through date, finite map expiry, one-hour session lifetime, code rotation/revocation terms and remaining durable usage. The old map expiry does not renew itself. Keep all source-positive limitations visible; do not transform ISSUED into OPEN, a building-year proxy into a roof installation date, or a current-PIN deed gap into legal continuity.

## Prepare media and submission locally

The dated release-assembly authority permits local integrated recording, captions, transcript and PR/access-package preparation after final runtime checks. Review every frame and artifact for secrets and protected observations. A locally playable demo is not an uploaded/reachable PR gate. Do not perform Git push, branch/fork mutation, PR/Ready transition, video upload, employer messaging, official submission, new public IPFS upload, Atlas/IPNS/on-chain or registry mutation. GitHub Actions is a post-push gate and cannot be reported executed beforehand.

## Close out safely

Remove temporary deployment access only through the authorized closeout flow; evaluator access and its retained review window are separate. Preserve new and rollback stacks, public artifacts and one compact reconstruction-grade return with checksums/verifier. Keep credentials, access codes and raw/private intake out of source and the return. Actual runtime teardown requires separate explicit approval, guarded inventory/export/revocation checks and the order in [deployment](DEPLOYMENT.md) and [cost/retention](COST_MODEL.md); preparation is not destruction authority.
