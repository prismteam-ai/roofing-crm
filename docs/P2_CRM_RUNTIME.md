# P2 CRM runtime and boundaries

The default local CRM reads Oracle's health-selected real public snapshot. It does not contain a county-data fallback or query any government source. Run the producer in explicit `PRISM_DATA_MODE=synthetic PRISM_ACCESS_MODE=local` mode for separate synthetic demonstrations; the consumer uses that reported mode and snapshot. A snapshot ID from the other process mode is rejected. The original README is preserved.

The web app calls `/api` on its own origin. Vite proxies to loopback 4311 locally. Hosted CloudFront routes `/api/*` to HTTP API and all other requests to private S3 with Origin Access Control. `VITE_ORACLE_STUDIO_URL` controls the separate Studio link at build time. No public map tiles, fonts, geocoder or remote asset calls occur by default. The map is a geographic coordinate plot, not a street map. An optional raster provider requires an exact approved HTTPS origin and visible attribution; embedded API keys and credentials are rejected. Provider terms, account, key mechanism and live requests remain later gates. Markers and click-to-pin use source coordinates; unknown positions are not invented.

The typed Oracle client supports exact deployment-approved HTTPS origins, same-origin resolution, and explicit loopback local use. It rejects URL credentials, paths, fragments, query strings, unapproved origins, hosted IP literals, redirects, and requests that exceed a bounded deadline. Hosted CRM forwards the shared signed review cookie only to the configured Oracle origin. There is no source scraping or privileged IAM authentication bypass.

## Authentication and storage

Oracle owns the identical `packages/hosted-runtime/src/{access,sessions,quota,secrets}.ts` modules copied here. Review-code validation produces a short-lived HMAC session with HttpOnly, Secure, SameSite=Strict, `/api` cookie scope. Session metadata, never the token, is stored in the shared Oracle-owned DynamoDB table with TTL. Every hosted data request verifies signature, key version, expiry and stored session. Logout deletes the session. Both applications must use the same secret ARN reference and session/quota table ARN. Configuration is lazily fetched from Secrets Manager and cached for 60 seconds; no secret is embedded in this repository or the frontend.

The CRM owns a separate DynamoDB lead table. Lead creation uses a transaction to bind an idempotency key and natural property/snapshot selection. Every successful idempotency alias is reserved, including natural-key deduplication and concurrent races; an alias cannot later be rebound to another property. SQLite migrates original request keys into its persistent binding table. Conditional version writes prevent lost updates. Session partition keys prevent cross-session reads. Status and note events remain append-only in the validated record. Audit history is preserved without truncation; a change that would exceed the 300 KB record bound is rejected before storage. Lead rows and idempotency bindings expire after 14 days; reads hide expired rows before eventual TTL removal. Local SQLite retains existing transaction/idempotency/version semantics. Local bypass requires explicit `PRISM_ACCESS_MODE=local` and is rejected inside Lambda.

Shared read/write/auth/model quotas use atomic conditional DynamoDB counters. Hosted defaults are 600 reads and 100 writes per session/hour, 10 shared access attempts/minute, 20 model requests per session/hour and 60 model requests globally/day. Reserved concurrency is 2. These are preparedness bounds, not a claim of an approved live spend budget. The live gate must set an authorized region/model and review window before deployment.

## Agent adapter

The deterministic provider remains the default. The real `BedrockRuntimeClient`/`ConverseCommand` adapter uses the same AI SDK typed search tool. It is enabled only through deployment configuration after the live inference gate. All P2 tests inject a fake Converse transport. No model call has been made.

The tool loop permits only read-only roofing search, fixes snapshot and center, cannot widen user predicates, and validates strict arguments. Limits are 3 model turns, 2 tool calls, 50 rows per tool result, 1,000 output tokens/call, 12,000 aggregate tokens with strict input/output/total consistency, a conservative input byte/token preflight, and a 15-second orchestration deadline. Global/session request limits combine with the per-request token ceiling. Unknown fields, arbitrary SQL/HTTP tools, cursor changes, injection attempts, malformed outputs and unsupported citations fail closed. The model selects property IDs from the latest evidence only. The application composes facts and citations directly from validated source rows instead of displaying unverified generated assertions. UI requests carry session and request generations. Logout/expiry immediately invalidates pending detail, lead refresh, search, mutation and agent completions; a late401 from a previous session cannot expire a newly opened session. Escape cancels pending detail intent. Source-reported contractor names remain separate from verified identity/license/rating. Optional roof evidence provenance and reported-sale events retain their source citations. Partial sale history is displayed as reported events and never treated as proof of ownership tenure.

## Local commands and proof

Use Node 24 and the frozen workspace lockfile. Install with `pnpm install --offline --frozen-lockfile --ignore-scripts` when the package store is populated. SDK packages are pinned at 3.1157.0; esbuild is 0.28.2. Dependency install hooks are disabled.

Run `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm lambda:package`, `pnpm lambda:emulate`, `pnpm cdk:synth`, and `pnpm benchmark`. Packaging produces a deterministic Linux Node24-compatible zip and byte/digest manifest under ignored `build/`. The CRM bundle has no native ABI dependency. Packaged hosted emulation also exercises the shared access protocol, session revocation, lead create/retry/version conflict, and the real orchestration code with an injected fake Converse transport. Ephemeral test access material is generated in memory and never printed. Emulation invokes the exact bundled API Gateway v2 handler and router locally with injected SQLite and synthetic Oracle dependencies; it is an equivalent event-boundary proof, not an AWS invocation. Local RSS/import/route timings describe the in-process harness and are not AWS cold-start or billing measurements. Oracle separately proves its native read-plane package.

`pnpm cdk:synth` performs no account lookup. Its assertions check a genuine asset handler, Node24, reserved concurrency, private S3/OAC, TTL, seven-day logs and scoped Bedrock resource permissions. Review resources use RETAIN; destruction needs an explicitly approved disposable stage. The frontend assets are included through the real S3 deployment resource. Shared session/quota table and secret ARN parameters reference Oracle-owned resources. Resource templates and packaging outputs remain local.

`pnpm deploy`, `pnpm smoke`, `pnpm evidence`, `pnpm rotate-access`, and `pnpm destroy` produce operation rehearsal plans only. They do not contact AWS or a hosted endpoint. An approved later live phase must supply account/region/model/resource references and execute the reviewed deployment/rotation/teardown procedure.

Browser tests run independently in real and explicit synthetic process modes. They wait for the applied query hash/generation, assert each returned row's predicates, map/list identity and empty/error behavior, and record screenshot sidecars with contract, snapshot/digest, exact query, URL, test, commit/tree and a working-file digest. Parent final validation captures clean final commits; preliminary captures are clearly marked dirty. Non-localhost requests are blocked and any attempted external request fails the suite.

The benchmark executes 1,000 real SQLite create/retry/update transactions using synthetic IDs, verifies persistence/history, and reports p50/p95/max plus database bytes. It makes zero network requests. It does not claim to benchmark county queries; Oracle owns full real snapshot and native read-plane measurements.

No AWS service, account login, model inference, source API, outreach, remote Git or public IPFS operation was used in this lane. Official documentation and public package downloads are recorded in the root return evidence. Current live spend is zero.
